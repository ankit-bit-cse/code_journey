2D arrays, recursion and binary search

1. A grid is an array of rows

const grid = [
  [3, 8, 1],   // row 0
  [6, 2, 9],   // row 1
];
grid[1][2];        // 9: row 1, then column 2
grid.length;       // 2: how many rows
grid[0].length;    // 3: how many columns

Always read it as row first, then column: grid[r][c]. The first [r] gives you a whole row (an array), and the second [c] picks a value from it.

2. Making a grid (and a nasty gotcha)

// Right: Array.from calls the function once per row,
// so each row is a NEW array.
const good = Array.from({ length: 3 }, () => new Array(4).fill(0));

// Wrong: fill puts the SAME row array in all 3 slots.
const bad = new Array(3).fill(new Array(4).fill(0));
bad[0][0] = 9;
bad;   // [[9,0,0,0], [9,0,0,0], [9,0,0,0]]  !!

Why? Remember Day 4: arrays are references. fill(x) copies the reference to the one row into every slot, so all the rows are really one row.

5. Recursion: a function that calls itself

Every recursive function has two parts:

  1. a base case: a tiny input you can answer right away, which stops the calls, and
  2. a smaller problem: call yourself on a smaller input, then use the answer.
function countdown(n) {
  if (n === 0) return;     // base case
  console.log(n);
  countdown(n - 1);        // smaller problem
}
countdown(3);   // 3, 2, 1

Forget the base case and the calls never stop: RangeError: Maximum call stack size exceeded.

6. Watch it run: the call stack during recursion

You met the call stack on Day 3. With recursion the same function stacks up many times, each with its own n. Each call waits until the one above it returns.

The stack grows on the way down to the base case, then shrinks on the way back up, and each return value is used by the call below it.

7. Binary search: halve it every time

In a sorted array, look at the middle item. If it is too small, the answer can only be to the right, so throw away the left half. If it is too big, throw away the right half. Keep two edges:

lo   // the first index still possible
hi   // the last index still possible
mid = Math.floor((lo + hi) / 2)

Below is the guessing game "I'm thinking of a number from 1 to 12". Each guess is the middle of what's left. The same lo, mid, hi moves work on an array, using arr[mid] instead of mid.

Only 4 guesses for 12 numbers. For 1,000,000 numbers it would be about 20.

8. Predict the output

Say the answer out loud first, then reveal.

[[1, 2], [3, 4]][1][0]

3. Row 1 is [3, 4], and its index 0 is 3.

const g = new Array(2).fill([]); g[0].push(5); g

[[5], [5]]. Both slots hold the same array. Use Array.from instead.

const f = (n) => n === 0 ? 0 : 1 + f(n - 1); f(4)

4. f(4) = 1 + f(3) = 1 + 1 + f(2) = ... = 1 + 1 + 1 + 1 + 0.

Binary search on [2, 4, 6, 8, 10]: what is the first mid?

2 (the index), so it looks at the value 6 first. lo = 0, hi = 4, and Math.floor(4 / 2) = 2.

Binary search on [5, 1, 4, 2] for 5

-1, even though 5 is right there! mid = 1 holds 1, which is less than 5, so it throws away the left half, and the 5 with it. Binary search only works on a sorted array.

the shapes of DSA

Grids describe boards, maps and mazes: "count the islands", "shortest path out of the maze". Recursion is the base of trees, backtracking and divide-and-conquer (merge sort splits an array in half and calls itself on each half). Binary search shows the power of O(log n): halving the problem every step, the same picture as Day 1.
