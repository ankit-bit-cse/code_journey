Map and Set

A Set answers "have I seen this?" in one step. A Map remembers something about each key. Together they turn slow O(n²) loops into fast O(n) ones.

← Day 7Day 9 →

1. Set: values with no duplicates

A Set is a bag that holds each value at most once. Adding something that is already inside does nothing.

const seen = new Set();
seen.add(3);
seen.add(5);
seen.add(3);      // already there: nothing changes
seen.has(3);      // true
seen.has(9);      // false
seen.size;        // 2   (size, not length)
seen.delete(5);   // removes 5

The famous one-liner to remove duplicates. The spread ... turns the Set back into an array:

[...new Set([3, 1, 3, 2, 1])];   // [3, 1, 2]

Order is kept. A Set remembers the order values were first added, so you get [3, 1, 2], not a sorted list.

2. Map: key → value, any key type

A Map is like the objects from Day 7, but made for lookups:

const age = new Map();
age.set("ankit", 20);
age.set("ravi", 25);
age.get("ankit");   // 20
age.get("mohan");   // undefined (missing key)
age.has("ravi");    // true
age.size;           // 2
age.set(7, "seven");
age.has("7");       // false: the key 7 stays a number

The counting idiom you know from Day 7 looks like this with a Map:

count.set(x, (count.get(x) || 0) + 1);

3. Looping over a Set or Map

for...of walks them in insertion order. A Map gives you [key, value] pairs, so unpack them:

for (const x of seen) {
  console.log(x);
}
for (const [name, years] of age) {
  console.log(name, years);
}
[...age.keys()];     // ["ankit", "ravi", 7]
[...age.values()];   // [20, 25, "seven"]

7. Sliding window: a Set that moves

Some questions look at a piece of a string or array that grows and shrinks. Keep two indexes, left and right, and a Set of what is inside the window:

// grow: take one more letter on the right
inWindow.add(s[right]);
// shrink: drop the letter on the left
inWindow.delete(s[left]);
left++;

Each letter enters the window once and leaves at most once, so the whole walk is O(n). Q8 uses exactly these two moves. Day 9 shows a sliding window step by step.

why lookups matter

arr.includes(x) walks the whole array: O(n). set.has(x) jumps straight to the answer: O(1). Inside a loop, that is the difference between these two:

// O(n²): includes walks the array every time
for (const x of a) if (b.includes(x)) ...

// O(n): build the Set once, then each has() is instant
const inB = new Set(b);
for (const x of a) if (inB.has(x)) ...

For 100,000 values, the first does about 10,000,000,000 steps and the second about 200,000. Reaching for a Set or Map is the most common way to speed up a slow DSA solution.
