Objects as hash maps

An object lets you jump straight to a value by its name, without searching. That one trick speeds up a huge number of DSA problems.

← Day 6Day 8 →

1. Keys and values

An object stores pairs: a key (the name) and a value.

const age = { ann: 31, bob: 25 };

age.ann;        // 31
age["bob"];     // 25
age.cat;        // undefined: a missing key is not an error
age.cat = 4;    // adds a new pair
age.ann = 32;   // changes an existing value

Think of it like an array whose indexes are words instead of 0, 1, 2.

2. Dot or brackets?

obj.key uses the key written in your code. obj[expr] works out the key first. When the key lives in a variable, you need brackets:

const name = "ann";
age[name];      // 31
age.name;       // undefined! looks for a key literally called "name"

for (const ch of "hi") {
  count[ch];    // count["h"], then count["i"]
}

To check whether a key exists, use in:

"ann" in age;   // true
"zed" in age;   // false

3. The counting idiom

The most useful line of the day:

count[k] = (count[k] || 0) + 1;

The first time we see k, count[k] is undefined, and undefined || 0 is 0. So a new key starts at 1. After that, it just adds 1.

4. Predict the output

Say the answer out loud first, then reveal.

const o = { x: 1 }; o.y

undefined. A missing key is not an error, which is exactly why the counting idiom needs || 0.

const k = "x"; const o = { x: 1 }; o.k

undefined. o.k means the key "k". You wanted o[k], which is 1.

const o = {}; o[5] = "five"; Object.keys(o)

["5"]. Object keys are always strings, so the number 5 became "5". Remember this for Q8.

const c = {}; c.a = (c.a || 0) + 1; c.a = (c.a || 0) + 1; c

{ a: 2 }. The first line makes it 1, the second makes it 2.

"a" in { a: 0 } vs { a: 0 }.a ? "yes" : "no"

true vs "no". The key exists, but its value 0 counts as false. Use in when you ask "is the key there?".

5. Watch it run: counting votes

Each array value is a vote for a fruit. Watch the object grow: a new key appears the first time we see a fruit, and after that its count just goes up.

One pass, and every lookup is instant. Count characters instead of words and you have Q1.

6. Watch it run: "have I seen it?"

Find two numbers whose difference is 4: an earlier value that is exactly 4 smaller than the current one. Instead of looking back through the array every time, we remember every value we have passed in a seen object (value → index).

The key move: ask first, then store. Change "difference" to "sum" and you have Q5.

trading memory for speed

Without a map, "is there an earlier number that fits?" means scanning back through the array: O(n) per number, O(n²) in total. With a map, each question takes about one step, so the whole thing is O(n). The price is the extra memory for the map.

// O(n²): look back every time
for (let j = 0; j < n; j++)
  for (let i = 0; i < j; i++)
    if (nums[i] + nums[j] === target) ...

// O(n): ask the map
for (let j = 0; j < n; j++)
  if ((target - nums[j]) in seen) ...

This "spend memory, save time" trade is one of the most common moves in DSA. Tomorrow, Map and Set do the same job with fewer surprises.
