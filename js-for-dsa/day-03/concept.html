1. Two ways to write a function

A function declaration and an arrow function do the same job:

function square(x) {
  return x * x;
}

const cube = (x) => x * x * x;          // one line: the value is returned for you
const half = (x) => { return x / 2; };  // with { }: you must write return

For everything in this track they behave the same. Arrows are handy for short helpers, and for passing a function into another function (section 6).

2. Parameters and default values

Parameters are the names in the brackets. They get their values when the function is called. Give a parameter a default with =, and it is used whenever the caller leaves that value out:

function greet(name, greeting = "Hello") {
  return greeting + ", " + name;
}
greet("Ankit");         // "Hello, Ankit"
greet("Ankit", "Hi");   // "Hi, Ankit"

3. Early return and block scope

return leaves the function immediately. Deal with the easy or strange cases first, then do the main work:

function safeDivide(a, b) {
  if (b === 0) return 0;   // edge case handled; nothing below runs
  return a / b;
}

A variable made with let or const only lives inside the { } where it was made:

for (let i = 0; i < 3; i++) {
  const sq = i * i;
}
console.log(sq);   // ReferenceError: sq is not defined

Why not var? var ignores { } blocks, so a loop variable leaks out and can clash with another one with the same name. Use const by default and let when the value changes. Never var.

4. Predict the output

Say the answer out loud first, then reveal.

const f = (x) => x + 1; then f(f(2))

4. The inner call runs first: f(2) is 3, then f(3) is 4.

function g(a, b = 10) { return a + b; } then g(5)

15. b was left out, so it takes its default, 10.

const h = (x) => { x * 2 }; then h(3)

undefined! Once you add { } to an arrow, nothing is returned unless you write return. A very common bug.

function check(n) { if (n > 0) return "pos"; return "not pos"; } then check(5)

"pos". The first return ends the function, so the second line never runs.

if (true) { let x = 1; } console.log(x);

A ReferenceError. x only lived inside the { }.

5. Pure functions vs functions that change their input

A pure function only reads its input and returns a new answer. Other functions mutate (change) the array you gave them. When you pass an array to a function, the function gets the same array, not a copy, so its changes are visible outside.

function doubledCopy(arr) {   // pure version: arr is untouched
  const out = [];
  for (let i = 0; i < arr.length; i++) out.push(arr[i] * 2);
  return out;
}

DSA habit: before you write a function, decide: "do I change the input, or return something new?" Questions will often say "in place" (change it) or "do not change the input" (pure).

6. Functions are values

A function can be stored in a variable and passed into another function, just like a number. The receiving function calls it with ():

const isEven = (v) => v % 2 === 0;

function firstMatch(arr, test) {
  for (let i = 0; i < arr.length; i++) {
    if (test(arr[i])) return arr[i];   // call whatever function we were given
  }
  return null;
}

firstMatch([3, 7, 8, 5], isEven);         // 8
firstMatch([3, 7, 8, 5], (v) => v > 6);   // 7

Notice isEven has no () when we pass it: we hand over the function itself, not its answer. On Day 9 you will pass functions to sort the same way.

helpers and the call stack

Good solutions are built from small helpers: once square exists, sumOfSquares is easy. When one function calls another, the caller waits. JavaScript keeps the waiting calls on a call stack: a new call goes on top, and a return takes it off.

The newest call always finishes first. On Day 10 a function will call itself (recursion), and this same stack is what makes it work.
