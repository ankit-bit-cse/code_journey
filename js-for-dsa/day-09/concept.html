Sorting, array methods and sliding window

map, filter and reduce are loops with a name. sort needs a comparator. And a window that slides saves you from adding the same numbers again and again.

1. map, filter, reduce: loops with a name

Each one takes a small function and calls it once for every item. Next to each, the loop it replaces:

const arr = [3, 8, 5];

// map: one output for every input -> a new array
arr.map((x) => x * 2);            // [6, 16, 10]
const out = [];
for (const x of arr) out.push(x * 2);

// filter: keep the items where you return true
arr.filter((x) => x > 4);         // [8, 5]
const kept = [];
for (const x of arr) if (x > 4) kept.push(x);

// reduce: boil everything down to one value
arr.reduce((acc, x) => acc + x, 0);   // 16
let acc = 0;
for (const x of arr) acc = acc + x;

They don't change arr. map and filter give back a new array. And they are still loops inside, so each one is O(n).

2. Watch it run: reduce, step by step

reduce carries one value, acc, from item to item. Whatever your function returns becomes the next acc. Here it keeps the biggest number so far.

The second argument (-Infinity here, 0 for a sum) is where acc starts. Always give it.

3. The sort gotcha

[10, 9, 1].sort();                  // [1, 10, 9]  !!
["b", "c", "a"].sort();             // ["a", "b", "c"]  fine for text

With no comparator, sort turns everything into text and compares like a dictionary. "10" comes before "9" because "1" comes before "9". For numbers, always pass a comparator:

[10, 9, 1].sort((a, b) => a - b);   // [1, 9, 10]  ascending
[10, 9, 1].sort((a, b) => b - a);   // [10, 9, 1]  descending
words.sort((a, b) => a.length - b.length);   // shortest first

4. Watch it run: a comparator deciding the order

This is insertion sort, a simple sort you can follow by hand. It only ever asks one question: "what does cmp(left, right) say?" A positive answer means the two are in the wrong order, so they swap. Here cmp sorts from biggest to smallest.

The built-in sort uses a faster method, but it asks your comparator the very same question.

5. sort changes the array, slice doesn't

const nums = [3, 1, 2];
const sorted = nums.sort((a, b) => a - b);
nums;     // [1, 2, 3]  the original changed too!

const safe = [...nums].sort((a, b) => a - b);   // copy first

Two names that look alike and do very different things:

const a = [10, 20, 30, 40];
a.slice(1, 3);    // [20, 30]  a copy from index 1 up to (not including) 3
a;                // [10, 20, 30, 40]  unchanged

a.splice(1, 2);   // [20, 30]  removes 2 items starting at index 1
a;                // [10, 40]  changed!

[1, 2, 3, 4].filter((x) => x % 2 === 1).map((x) => x * 10)

[10, 30]. filter keeps 1 and 3, then map multiplies each by 10. You can chain them.

[].reduce((acc, x) => acc + x, 0)

0. There is nothing to add, so you just get the starting value back. Without the 0 this would crash.

"cab".split("").sort().join("")

"abc". Split into letters, sort them (text sort is right for letters), glue them back.

[7, 8, 9].slice(-2)

[8, 9]. A negative index counts from the end: the last two items.

7. Watch it run: a sliding window

We want the sum of every group of 3 neighbours. Adding 3 numbers for each group repeats work. Instead, the window slides: one number enters on the right (R), one leaves on the left (L).

Each step costs one add and one subtract, no matter how big the window is. Q8 is the same slide, but it keeps only the best sum.

sort first, then think

A good sort takes about n log n steps. That's a little more than one pass, and it often turns a hard problem into an easy one:

  • the k-th largest is just an index after sorting,
  • two words are anagrams if their sorted letters are equal,
  • duplicates end up next to each other,
  • and on Day 10, binary search only works on a sorted array.

The sliding window is the other big idea: checking every group of k neighbours drops from O(n·k) to O(n).
