Arrays: traversal and linear search

Most DSA problems hand you an array. Learn to walk through it with an index, one box at a time.

← Day 3Day 5 →

1. Boxes with numbers on them

An array is a row of boxes. Each box has an index, starting at 0.

const a = [7, 3, 9];
a[0];              // 7
a.length;          // 3
a[a.length - 1];   // 9: the last box is always at length - 1
a[1] = 4;          // a is now [7, 4, 9]

No error for a wrong index: a[5] and a[-1] just give undefined. Your code keeps running with a wrong value, so check your loop bounds carefully.

2. Adding and removing

MethodDoesCost
a.push(x)add at the endO(1), fast
a.pop()remove and return the lastO(1), fast
a.unshift(x)add at the frontO(n): every box moves right
a.shift()remove and return the firstO(n): every box moves left

Working at the end of an array is cheap. Working at the front means renumbering every box.

3. Two ways to walk through an array

for (let i = 0; i < a.length; i++) {   // you need the index
  console.log(i, a[i]);
}

for (const x of a) {                   // you only need the values
  console.log(x);
}

Use the index loop when the answer is a position, or when you need a neighbour like a[i - 1]. Use for...of when you only look at values, like adding them up.

4. Watch it run: find the first negative

A linear search moves the pointer i from the left, one box at a time, and stops as soon as it finds what it wants.

Two exits: return i the moment we find it, or return -1 after the loop if we never did. includes and indexOf are this same loop. Today, write it yourself.

5. Keeping the best so far

To find the biggest value, remember the best one seen so far and challenge it with each new box. Start with -Infinity, which every number beats (Day 1).

Remember the index instead of the value and you have Q3. Keep a first and a second best and you have Q6.

6. Predict the output

Say the answer out loud first, then reveal.

const a = [4, 8, 1]; a[a.length]

undefined. The last index is length - 1, which is 2. Index 3 does not exist.

const a = [4, 8, 1]; a.push(6); a.length

4. push added a box at the end.

const a = [4, 8, 1]; const x = a.shift(); then x and a

4 and [8, 1]. shift removes the first box, returns it, and every other box moves one place left.

const a = [1, 2]; const b = a; b.push(3); then a

[1, 2, 3]. b = a does not copy. Both names point at the same array.

[1, 2] === [1, 2]

false! === on arrays asks "is this the same array?", not "do they hold the same values?". Two separate arrays are never ===.

7. Arrays are references

A variable does not hold the array itself. It holds a reference, like an address. b = a copies the address, so both names lead to one array. To get a real, separate copy use [...a] or a.slice().

DSA habit: if a question says "do not change the input", copy it first with [...arr] and work on the copy.

linear search is O(n)

A linear search may have to look at every box, so its cost grows with the array: n boxes, up to n checks. That is O(n), and it's fine for one search.

// a search inside a loop: n rounds × n checks = O(n²)
for (const x of a) {
  if (b.includes(x)) count++;   // includes is a hidden loop!
}

Watch out for hidden loops like includes, indexOf and shift inside your own loop. On Day 8 a Set makes that lookup O(1), and on Day 10 binary search finds things in a sorted array in O(log n).
