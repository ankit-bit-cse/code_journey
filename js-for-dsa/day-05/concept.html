Arrays in place: swap and two pointers

Two index variables walking through one array can do a lot of work without ever making a copy.

← Day 4Day 6 →

1. Change it, or build a new one?

A function can change the array it was given (we say "in place"), or build a new array and leave the input alone.

function doubleInPlace(arr) {   // changes arr itself
  for (let i = 0; i < arr.length; i++) arr[i] = arr[i] * 2;
  return arr;
}

function doubled(arr) {         // arr is not touched
  const out = [];
  for (const x of arr) out.push(x * 2);
  return out;
}

In place needs no extra array, so it uses O(1) extra space. Today's questions say which kind they want. Read carefully.

2. Swapping two values

If you write arr[i] = arr[j] first, the old arr[i] is gone. Park it in a temporary variable:

const temp = arr[i];
arr[i] = arr[j];
arr[j] = temp;

JavaScript also has a one-line version. It builds a little array on the right and unpacks it on the left:

[arr[i], arr[j]] = [arr[j], arr[i]];

3. Predict the output

Say the answer out loud first, then reveal.

let a = 1, b = 2; a = b; b = a; → what are a and b?

Both are 2. The old value of a was overwritten before it was saved. That's why you need temp.

const x = [1, 2, 3]; const y = x; y[0] = 9; → x?

[9, 2, 3]. x and y are the same array. Changing an array in place changes it for everyone holding it.

With arr = [4, 8]: [arr[0], arr[1]] = [arr[1], arr[0]]

arr becomes [8, 4]. The right side [8, 4] is built first, then unpacked into the two slots.

For [1, 2, 3, 4, 5], how many times does while (left < right) run?

2. (0,4) then (1,3). Then both pointers are at 2, so left < right is false. The middle element never needs to move.

4. Watch it run: two pointers from both ends

Here we reverse only the middle part of an array, from index 1 to index 4. lo and hi swap, then step toward each other. Press Play, or step with Next.

Set lo = 0 and hi = arr.length - 1 and you have reversed the whole array (Q2). Compare instead of swap and you have a palindrome check (Q3).

5. Watch it run: read and write pointers

Now both pointers go the same way. read looks at every value. write only moves when we keep one. Here we drop the negative numbers and keep the rest in order.

Everything left of write is the finished answer. The same idea moves zeros to the end (Q4) and squeezes out duplicates (Q5).

6. Merging two sorted arrays

Put one pointer at the front of each array. Take the smaller front value, then move that pointer:

a = [1, 4, 7]     b = [2, 3, 8]
     i                 j        1 < 2, take 1, i++
        i              j        4 > 2, take 2, j++
        i                 j     4 > 3, take 3, j++
        ...
out = [1, 2, 3, 4, 7, 8]

When one array runs out, copy whatever is left in the other. That's Q7.

from n² to n

"Find two numbers in a sorted array that add up to 10." The slow way tries every pair with two nested loops: about n² steps. With two pointers, each step moves left or right by one and they never go back, so it takes at most n steps:

sum too small?  left++    (the only way to get bigger)
sum too big?    right--   (the only way to get smaller)

The same "never go back" pointers power merge sort, removing duplicates, and the sliding window on Day 9.
