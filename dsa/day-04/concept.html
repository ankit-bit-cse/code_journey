Recursion on arrays and strings

Yesterday recursion worked on numbers. Today it walks along arrays and strings with an index, dives into arrays inside arrays, and builds whole lists of answers.

← Day 3Day 5 →

1. Slicing hides a loop

In JS for DSA you summed an array like this. It reads nicely:

function sum(arr) {
  if (arr.length === 0) return 0;
  return arr[0] + sum(arr.slice(1));   // the rest, as a NEW array
}

But slice(1) is not free. It copies every remaining element into a new array (Day 2: slice is O(k)). For 5 elements the calls copy 4, 3, 2, 1 and 0 values:

sum([4, 7, 1, 6, 2])   copies 4 values
 sum([7, 1, 6, 2])     copies 3
  sum([1, 6, 2])       copies 2
   sum([6, 2])         copies 1
    sum([2])           copies 0      total: n(n-1)/2  →  O(n²)

Hidden cost. One line of code, but O(n) work inside each call, so O(n²) in total. And every copy is still alive while the calls below it run, so it eats O(n²) memory too.

2. Pass an index instead

Keep the one array and tell each call where to start. "The rest of the array" is just i + 1:

function sumFrom(arr, i = 0) {
  if (i === arr.length) return 0;        // base case: nothing left
  return arr[i] + sumFrom(arr, i + 1);   // this element + the rest
}
sumFrom([4, 7, 1, 6]);   // 18 (i starts at 0 by default)
  • Base case: the index has walked off the end, so the rest is empty.
  • Smaller problem: the same array, one index later.
  • Trust: assume sumFrom(arr, i + 1) already works, and only add arr[i].

Each call now does O(1) work, so the whole thing is O(n) time. The stack still holds one call per element: O(n) space.

3. Watch it run: the index walks, the stack grows

The arrow i moves right as each call is made. The calls pile up on the stack, each waiting for the one above it. At the end the answers come back down, adding one element each.

Count the calls: 4 elements, 5 calls (the last one is the base case). One call per element plus one: O(n).

4. Helper functions carry extra parameters

Sometimes the question gives you f(arr), but your recursion wants more: an index, a string built so far, an output array. Put a helper inside and let it carry them. Inner functions can see the outer variables (Day 3 of JS for DSA: scope).

function evensOf(arr) {
  const out = [];               // one shared result
  function helper(i) {
    if (i === arr.length) return;          // base case
    if (arr[i] % 2 === 0) out.push(arr[i]);
    helper(i + 1);                         // the rest
  }
  helper(0);
  return out;
}
evensOf([3, 8, 2, 5]);   // [8, 2]

Strings work the same way: s[i] is one character and i === s.length means nothing is left.

Two classic bugs. Calling helper(i) instead of helper(i + 1) never gets smaller, so it crashes with Maximum call stack size exceeded. And in a function that returns a value, forgetting the return in return f(arr, i + 1) hands undefined back.

6. Arrays inside arrays

[[8, [6]], 3, [[5], 1]] is a little tree: some items are numbers, some are arrays, which hold more items. You can't know how deep it goes, so no fixed number of loops can handle it. Recursion can:

for (const item of arr) {          // ACROSS one level: a loop
  if (Array.isArray(item)) {
    walk(item);                    // DOWN into a level: recursion
  } else {
    // a plain number: do something with it
  }
}

Where is the base case? An array with only numbers in it makes no recursive calls, so the recursion stops there by itself.

7. Watch it run: unwrapping nested arrays

Here we collect the odd numbers from a nested array into one shared out array. Watch the stack grow each time we step into an inner array, and shrink when that array is finished.

Every number is visited once and every array is entered once. Drop the "is it odd?" check and you have flatten (Q6).

8. Take or skip: recursion that builds every answer

"Which subsets of [1, 2, 4] are there?" Look at the elements one at a time and make a choice: take it or skip it. Each call makes two calls, so it forms a tree with 2 × 2 × 2 = 8 leaves, one per subset.

                 i=0, sum 0
          take 1 /        \ skip 1
         i=1, 1             i=1, 0
      take 2 / \ skip     take 2 / \ skip
        ...     ...         ...     ...     (8 leaves)

Below, the helper carries i (which element we decide next) and sum (the total of what we took). When every element is decided, the sum is one finished answer. "Take" is always tried first, so the answers come out in a fixed order.

Grows fast. 2ⁿ answers means 20 elements already give over a million. Take/skip is the right tool when you really need every combination, and tomorrow you will see how to avoid repeating work when you don't.

where these shapes come back

Index recursion is how merge sort and quick sort work on one array (Days 8 and 9): they pass lo and hi instead of copying halves. Nested arrays are your first trees: "walk every child, recurse into it" is exactly the tree traversal of Phase 4. Take or skip is backtracking, the engine behind interview classics like Subsets, Combination Sum and Generate Parentheses. And the grid-paths question is the first problem of dynamic programming, which starts tomorrow with memoization.
