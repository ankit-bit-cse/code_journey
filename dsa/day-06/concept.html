Bubble sort and selection sort

Until now .sort() did the work. Today you look inside: two simple sorts, step by step, counting every comparison and every swap.

← Day 5Day 7 →

1. Words for sorting

wordmeaning
comparisonlook at two values and ask which is bigger. We count these to measure a sort.
swapexchange two values: [a[i], a[j]] = [a[j], a[i]];
passone walk through (part of) the array
in placethe sort only moves values inside the array: O(1) extra space
stableequal values keep the order they had before sorting

Why learn slow sorts when .sort() exists? Because their ideas come back everywhere: "push the biggest to the end", "pick the smallest of the rest", "count the swaps", "stop early when nothing changes". And interviewers love to ask what a sort costs and whether it is stable.

2. Bubble sort: the biggest bubbles to the end

Walk from left to right and compare each pair of neighbours. If the left one is bigger, swap them. The biggest value gets picked up and carried along until it reaches the end: one pass puts it in its final place.

[5, 1, 4, 2]     5 > 1 swap
[1, 5, 4, 2]     5 > 4 swap
[1, 4, 5, 2]     5 > 2 swap
[1, 4, 2, 5]     pass done: 5 is final

Then do it again on the part that is not final yet. Pass i (from 0) leaves i + 1 values finished at the end, so its inner loop can stop at j < n - 1 - i. After n - 1 passes everything is in place.

Off by one. The inner loop reads a[j + 1], so j must stop at n - 2. Write j < n - 1, not j < n, or the last comparison reads undefined.

3. Watch it run: bubble sort with early exit

The two arrows are the pair being compared. Yellow means "comparing", green is the finished tail growing from the right. Keep an eye on swapped: when a whole pass ends with it still false, the array is sorted and we stop early.

A plain bubble sort would do 5 passes here. The early exit stopped after 3, because the third pass found nothing to fix.

4. Best case, worst case, and counting swaps

  • Already sorted: the first pass makes no swap, so with the early exit it is 1 pass, n - 1 comparisons: O(n).
  • Reversed: every comparison swaps and no pass can stop early: n(n-1)/2 comparisons and swaps, O(n²).
  • Average: still O(n²).

Each swap fixes exactly one pair of values that were in the wrong order. Such a pair is called an inversion. So bubble sort's number of swaps is exactly the number of inversions: [3, 1, 2] has 2 (3 before 1, 3 before 2), and bubble sort makes 2 swaps on it.

Stable for free. Bubble sort only swaps when the left value is strictly bigger, and only next-door neighbours. Two equal values never jump over each other, so their order is kept. Change > to >= and it is no longer stable (and does useless swaps).

5. Selection sort: pick the smallest of the rest

A different idea. For each position i from the left: find the smallest value in a[i..], then swap it into position i. Remember the index of the smallest so far (not the value), so you know where to swap from.

[7, 4, 9, 2]    smallest of all is 2 (index 3): swap with index 0
[2, 4, 9, 7]    smallest of a[1..] is 4: already there, swap with itself
[2, 4, 9, 7]    smallest of a[2..] is 7: swap with index 2
[2, 4, 7, 9]    done

Invariant: before step i, a[0..i-1] holds the i smallest values, in order, and they never move again.

6. Watch it run: selection sort with a min pointer

i marks the place to fill, j scans the rest, and min jumps whenever j finds something smaller. One swap at the end of each step.

15 comparisons for 6 values, n(n-1)/2, and it would be exactly the same for a sorted array: selection sort can't stop early. But it made only 4 swaps (never more than n - 1).

7. Selection sort is not stable

Label two equal values so you can tell them apart: 2a and 2b. Watch the long jump in the first step:

[2a, 2b, 1]     smallest is 1 (index 2): swap it with index 0
[1, 2b, 2a]     2a jumped over 2b!
                the 2s are now in the wrong order, and nothing moves them back

With numbers you can't see the difference, but when you sort people by age, or orders by date, an unstable sort can shuffle the ones that tie. Tomorrow's insertion sort is stable, and so is JavaScript's .sort().

8. Predict the output

Say the answer out loud first, then reveal.

One bubble pass on [4, 3, 2, 1]

[3, 2, 1, 4]. The 4 is carried all the way to the end; everything else moves only one place left.

Bubble sort with early exit on [1, 2, 3, 4, 5]: how many passes and comparisons?

1 pass, 4 comparisons. No swap in the first pass, so it stops. That is the O(n) best case.

How many swaps does bubble sort make on [2, 3, 1]?

2. The inversions are (2, 1) and (3, 1).

Selection sort on [1, 2, 3, 4, 5]: how many comparisons?

10 = 4 + 3 + 2 + 1. It still scans the whole rest every step, because it can't know the rest is sorted.

After 2 steps of selection sort, [8, 5, 9, 1, 3] is…

[1, 3, 9, 8, 5]. Step 0 swaps 1 into front, step 1 swaps 3 into index 1. The first 2 values are already the 2 smallest, in order.

Don't change the input. Today's questions return a sorted copy. const a = [...arr]; first, then swap inside a. The copy is O(n) space, but the sort itself is still in place.

where these ideas come back

Nobody ships bubble sort, but interviews ask about its pieces. "How many swaps / inversions?" comes back on Day 8, where merge sort counts inversions in O(n log n) instead of O(n²). Stopping selection sort after k steps is the first answer to K smallest elements; quickselect (Day 9) and heaps (Phase 4) do it faster. "Fewest swaps" is selection sort's strength: when writing to memory is expensive, n - 1 swaps beats n². And the stability question decides which sort you may use when sorting records by several keys, which is tomorrow's topic.
