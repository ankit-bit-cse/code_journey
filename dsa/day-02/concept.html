Space complexity and the cost of built-ins

Time is not the only bill: memory counts too. And one innocent-looking method call like includes or shift can hide a whole loop. Today you learn to see both.

← Day 1Day 3 →

1. Space complexity: the extra memory

Space complexity counts the extra memory an algorithm needs on top of its input, as the input grows. The input itself is not counted: it was there anyway.

function sum(arr) {
  let total = 0;                 // one number, whatever n is
  for (const x of arr) total += x;
  return total;
}                                // extra space: O(1)

function doubled(arr) {
  const out = [];                // grows to n items
  for (const x of arr) out.push(x * 2);
  return out;
}                                // extra space: O(n)

function table(n) {
  return Array.from({ length: n }, () => new Array(n).fill(0));
}                                // extra space: O(n²)

A handful of variables is O(1) space, no matter how big the input is. A new array, Set, Map or string that grows with the input is O(n).

The output can count. If a question asks you to return a new array, that O(n) is unavoidable. When people say "O(1) space" they usually mean "O(1) besides the output".

2. In place vs making a copy

Working in place means changing the input array itself instead of building a new one. You did this in JS for DSA Day 5 with two pointers.

// O(n) extra space: a whole new array
const rev = [...arr].reverse();

// O(1) extra space: swap the ends inward
let lo = 0, hi = arr.length - 1;
while (lo < hi) {
  [arr[lo], arr[hi]] = [arr[hi], arr[lo]];
  lo++; hi--;
}

Both are O(n) time. The difference is memory. For a million numbers, the copy needs another few megabytes; the in-place version needs two numbers.

In place changes the caller's array. Arrays are passed by reference, so whoever called your function sees the change. Only do it when the question asks for it (like Q8).

3. Best, worst and average case

The same code can take a different number of steps on different inputs of the same size. Linear search:

function find(arr, x) {
  for (let i = 0; i < arr.length; i++) {
    if (arr[i] === x) return i;
  }
  return -1;
}

When someone says "linear search is O(n)", they mean the worst case. That is the default: it is a promise that holds for every input. The best case is rarely interesting ("it's fast if you're lucky").

4. What JavaScript's built-ins really cost

A method call is one line, but not one step. Inside, many of them loop over the array:

OperationTimeWhy
arr[i], arr.lengthO(1)jumps straight to the slot
push, popO(1)*work at the end, nothing moves (* amortized, section 6)
shift, unshiftO(n)every other item moves one slot
splice(i, ...)O(n)everything after i moves
includes, indexOf, findO(n)a linear search
slice(a, b)O(b − a)copies that many items
[...arr], concat, map, filterO(n)build a new array: O(n) space too
sortO(n log n)a real sorting algorithm (Days 8–9)
set.has, set.add, map.get, map.setO(1) on averagea hash jumps to the right bucket
str.split, arr.join, Object.keysO(n)visit every item

A hidden loop inside a loop is O(n²). for (x of a) if (b.includes(x)) looks like one loop, but each includes is a loop over b. Same trap: shift() or splice() inside a loop.

5. Watch it run: includes() scans, Set.has() jumps

Looking for 9, then 5, in the same 8 numbers. includes compares one item at a time. A Set stores each value in a bucket picked by a quick calculation on the value (here, simplified: value % 8), so it only looks in one bucket.

Building the Set costs O(n) once. After that, each lookup is O(1). If you look up many values, that trade is a huge win: Q1, Q3 and Q4 all use it.

6. Amortized: why push is O(1)

An array lives in a block of memory with some spare room. When the room runs out, JavaScript grabs a block about twice as big and copies everything over. That copy is O(n), but it happens rarely:

Push numberRoom (before → after)Copies
10 → 10
21 → 21
32 → 42
54 → 84
98 → 168
other pushesroom left0

For 16 pushes the copies add up to 1 + 2 + 4 + 8 = 15, less than 16. Spread over all the pushes, that is less than one extra step each. "Amortized O(1)" means: one push may be slow, but n pushes cost O(n) in total.

Strings don't get this deal. Strings can't be changed, so s += ch may build a brand new string each time: n appends can cost 1 + 2 + ... + n = O(n²). Modern engines often optimise it, but the safe habit is: push the pieces into an array, then join("") once.

7. Spend space to save time: prefix sums

Many questions ask the sum of a range arr[l..r], again and again. Looping each time is O(n) per question. Instead, build one extra array once:

// prefix[i] = sum of the first i values, so prefix[0] = 0
const prefix = [0];
for (const x of arr) prefix.push(prefix[prefix.length - 1] + x);

Now the sum of arr[l..r] is "everything up to r" minus "everything before l". Watch it build, then answer three ranges with one subtraction each:

O(n) time and O(n) space to build, then O(1) per query. With q queries: O(n + q) instead of O(n · q).

8. Predict the output

Say the answer out loud first, then reveal.

Time of: for (const x of a) if (b.includes(x)) count++; (both have n items)

O(n²). n rounds, and each includes scans up to n items. With const s = new Set(b) and s.has(x) it becomes O(n).

Time of: while (queue.length) { const x = queue.shift(); ... }

O(n²). Each shift moves every remaining item. Reading with an index (queue[head++]) makes it O(n).

Extra space of: const rev = arr.slice().reverse();

O(n). slice() copies the whole array. reverse() itself works in place, on the copy.

Comparisons for [4, 8, 15].indexOf(4), and for .indexOf(42)?

1 and 3: best case and worst case. A missing value always costs a full scan.

prefix = [0, 2, 6, 7, 10] (from [2, 4, 1, 3]). Sum of arr[1..2]?

5 = prefix[3] − prefix[1] = 7 − 2. That is 4 + 1.

where this shows up

Interviewers almost always follow "what's the time complexity?" with "and the space?", and then "can you do it in O(1) extra space?". The classic answers: two pointers and read/write pointers (in place, O(1)), versus a Set or Map (O(n) space bought for O(n) time).

Spotting hidden loops (includes, shift, splice, slice in a loop) is how you find why a "correct" solution gets Time Limit Exceeded. Prefix sums come back in Phase 2 for "subarray sum equals k" and range problems, and in-place tricks power the sorting days.
