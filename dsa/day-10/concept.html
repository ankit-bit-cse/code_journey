Binary search templates

You already know binary search finds x in O(log n). Today you learn to write any binary search (first, last, how many, where would it go) without off-by-one bugs, by deciding what lo and hi mean before you write a single line.

← Day 9Day 11 →

1. Why "find x" is not enough

The binary search from JS for DSA Day 10 answers one question: is x here, and where? On [2, 4, 4, 4, 6] searching for 4, it stops at index 2, the middle 4. But interviews ask more:

  • Where is the first 4? Where is the last 4? How many 4s are there?
  • 5 isn't there. Where would it go?
  • What is the biggest value that is still ≤ 5?

Each one is a binary search with a slightly different loop. Guessing the < vs <= and the + 1s until the tests pass is how off-by-one bugs are born. Instead, we pick an invariant: a sentence about lo and hi that stays true every step.

2. Two templates, two meanings of hi

closed range [lo, hi]half-open range [lo, hi)
startlo = 0, hi = n - 1lo = 0, hi = n
hi meansthe last index still possibleone past the last index still possible
loopwhile (lo <= hi)while (lo < hi)
moveslo = mid + 1 / hi = mid - 1lo = mid + 1 / hi = mid
ends withlo === hi + 1: nothing leftlo === hi: one answer left
best forfind x, "best answer so far"lower / upper bound, "first index where…"

The loop condition follows from the meaning: in [lo, hi] the range is empty when lo > hi, so keep going while lo <= hi. In [lo, hi) it is down to one answer when lo === hi, so keep going while lo < hi.

Pick one meaning and never mix them. Most bugs are a loop written for one template with moves from the other.

3. Lower bound: the first index with arr[i] ≥ x

function lowerBound(arr, x) {
  let lo = 0, hi = arr.length;     // the answer can be arr.length
  while (lo < hi) {
    const mid = Math.floor((lo + hi) / 2);
    if (arr[mid] >= x) hi = mid;   // mid COULD be the answer: keep it
    else lo = mid + 1;             // mid is too small: drop it
  }
  return lo;                       // lo === hi: the one answer left
}

Invariant: the answer is always inside [lo, hi]. When arr[mid] >= x, mid might be the first such index, so we can't throw it away: hi = mid, not mid - 1. When arr[mid] < x, mid and everything left of it are too small: lo = mid + 1.

Picture the array as a row of "no, no, no, yes, yes" answers to is arr[i] ≥ x?. Lower bound finds the first "yes". If there is no "yes" at all, the answer is arr.length, which is why hi starts there.

5. Upper bound, and what the pair gives you

Upper bound is the first index with arr[i] > x (strictly bigger). It is lower bound with one character changed: arr[mid] > x instead of >=.

arr = [2, 3, 5, 5, 5, 5, 8, 9]
lowerBound(arr, 5)   // 2: the first 5
upperBound(arr, 5)   // 6: just past the last 5

// the 5s are the block [lowerBound, upperBound)
first 5   = lowerBound(arr, 5)          // 2
last 5    = upperBound(arr, 5) - 1      // 5
how many  = upperBound(arr, 5) - lowerBound(arr, 5)   // 4

lowerBound(arr, 6)   // 6  and  upperBound(arr, 6)  // 6
// 6 is missing: both bounds land on the same spot, so 6 - 6 = 0

Check before you read. A bound can be arr.length, which is off the end. For "first x", test i < arr.length && arr[i] === x before you say you found it.

7. mid without overflow

const mid = Math.floor((lo + hi) / 2);       // fine in JavaScript
const mid2 = lo + Math.floor((hi - lo) / 2);  // the same number, overflow-safe

In Java or C++, lo + hi is an int and can overflow past about 2.1 billion, so they write lo + (hi - lo) / 2. JavaScript numbers are exact up to 2⁵³, so Math.floor((lo + hi) / 2) is safe, but you'll see the other form in interview solutions: now you know it's the same thing.

Don't use (lo + hi) >> 1 on big numbers. >> turns its input into a 32-bit integer first, so it breaks above about 2.1 billion. On Day 12 the search range can be that big.

8. Watch it run: an off-by-one that never ends

Here someone wants the last index with arr[i] <= x, uses while (lo < hi), and writes lo = mid because mid might be the answer. Looks reasonable. Watch what happens when only two candidates are left.

The rule: with while (lo < hi), every step must shrink the range. hi = mid always does (mid < hi), but lo = mid doesn't when mid === lo. Either round mid up with Math.floor((lo + hi + 1) / 2), or (easier) switch to the closed template with ans from section 6.

9. Predict the output

Say the answer out loud first, then reveal. arr = [1, 3, 3, 3, 7] for all of them.

lowerBound(arr, 3) and upperBound(arr, 3)

1 and 4. The 3s fill indices 1, 2, 3, so there are 4 - 1 = 3 of them.

lowerBound(arr, 8)

5, which is arr.length. Nothing is ≥ 8, so the answer is "off the end". Reading arr[5] gives undefined.

lowerBound(arr, 0) and upperBound(arr, 0)

0 and 0. Everything is bigger than 0, so both bounds are the very first index, and the count of 0s is 0 - 0 = 0.

The classic lo <= hi search for 3: which index does it return?

2. lo = 0, hi = 4, mid = 2, and arr[2] is 3, so it stops. It found a 3, not the first one. That is why we need lower bound.

The classic search for 5 (not there): what are lo and hi when the loop ends?

lo = 4, hi = 3. mid 2 (3 < 5, lo = 3), mid 3 (3 < 5, lo = 4), mid 4 (7 > 5, hi = 3). lo is 4: exactly where 5 would be inserted. You'll use this in Q7.

10. An off-by-one checklist

  1. Write the invariant first. "The answer is in [lo, hi]" or "in [lo, hi)". Say it out loud.
  2. Loop condition from the invariant: closed → lo <= hi, half-open → lo < hi.
  3. Every move keeps the invariant: only drop indices you are sure are not the answer.
  4. Every move shrinks the range, or the loop runs forever.
  5. Test the edges: empty array, one element, x smaller than everything, x bigger than everything, all elements equal.

where bounds show up

Lower and upper bound are the bricks of every binary search to come. Tomorrow you'll search rotated arrays and find peaks; on Day 12 you'll binary search over the answer itself ("what is the smallest speed that works?"), which is a lower bound on a yes/no question. In interviews: "find first and last position of an element", "search insert position", "count of x in a sorted array", "floor and ceiling", "k closest elements". Other languages ship these as bisect_left / bisect_right (Python) and lower_bound / upper_bound (C++).
