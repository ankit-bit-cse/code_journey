Time complexity: counting steps

How fast is a piece of code? Not in seconds, which change with every laptop, but in steps: how many times its lines run as the input grows. Count them, keep the biggest term, and you have its Big-O.

← All daysDay 2 →

1. Count how often each line runs

In JS for DSA Day 2 you met O(n) and O(n²) as names. Today we go one level deeper: for each line, write down exactly how many times it runs for an input of size n.

function sumAndMax(arr) {        // n = arr.length
  let sum = 0;                   // 1 time
  let max = -Infinity;           // 1 time
  for (const x of arr) {
    sum += x;                    // n times
    if (x > max) max = x;        // n times
  }
  return [sum, max];             // 1 time
}

Total: 2n + 3 steps. For n = 10 that is 23, for n = 1,000,000 it is 2,000,003. The shape is what matters: double n and the work doubles. That is O(n), linear time.

A "step" is any simple operation: one comparison, one addition, one assignment, one array read. We don't care whether a line is 1 step or 3: that only changes the constant in front, and constants get dropped (section 3).

2. Counting a loop whose length changes

When the inner loop depends on the outer one, add up the rounds one by one:

for (let i = 0; i < n; i++)
  for (let j = i; j < n; j++)   // j starts at i
    steps++;

For i = 0 the inner loop runs n times, for i = 1 it runs n − 1 times, ..., for the last i it runs once. So the total is n + (n − 1) + ... + 2 + 1.

The Gauss trick. Write the sum forwards and backwards under each other:

  1   +   2   + ... + (n-1) +   n
  n   + (n-1) + ... +   2   +   1
-------------------------------------
(n+1) + (n+1) + ... + (n+1) + (n+1)    // n columns

Each column adds to n + 1 and there are n columns, so twice the sum is n(n + 1), and the sum is n(n + 1) / 2. For n = 5: 5 · 6 / 2 = 15. You will use this trick in Q2 and Q6.

3. Drop the constants and the smaller terms

Big-O describes how the step count grows for big n. Two rules turn any formula into its Big-O:

  1. Keep only the biggest term. In n² + 100n + 7, for n = 1,000,000 the n² part is 10¹² and the 100n part is only 10⁸. The small terms stop mattering.
  2. Drop the constant in front. 2n + 3 and 50n are both O(n): doubling n doubles both.

Two inputs, two letters. A loop over a followed by a loop over b is O(n + m), not O(n). A loop over a with a loop over b inside it is O(n · m). Don't squash different sizes into one n.

4. Watch it run: a step counter in nested loops

The section 2 loop for n = 5. Each grid cell is one pair (i, j): row i, column j. A cell gets a number when steps++ runs for that pair. Watch the triangle fill: that triangle is why the count is about half of n².

15 = 5 · 6 / 2, just as Gauss said. The full square would be 25 = n²; the triangle is a bit more than half of it. Half of n² is still O(n²).

Why is halving log n? log₂ n answers "how many times can I halve n before I reach 1?". 16 → 8 → 4 → 2 → 1 is 4 halvings, and log₂ 16 = 4. A loop that multiplies by 2 (i *= 2) up to n is the same count, read the other way.

Subtracting is not halving. while (n > 0) n -= 2; runs n / 2 times: that is still O(n). Only dividing (or multiplying) by a constant each step gives log n.

6. Watch it run: linear vs halving, side by side

Both loops start on n = 16 and take one step per tick. The i pointer walks one box at a time; the m pointer jumps to half of what is left. Watch who finishes first.

For n = 16 the halving loop needs 4 steps against 16. For n = 1,000,000 it needs only 19 against a million: that gap is the whole point of binary search (Days 10–12).

A computer does roughly 10⁸ simple steps per second. So 10¹² steps is about 3 hours, and 2¹⁰⁰ steps would not finish before the sun burns out. Each row is a different world: no faster laptop moves you from O(n²) to O(n), only a better idea does.

Big-O is about big n. For n = 10, an O(n²) loop (100 steps) can beat an O(n) loop with a heavy body. Big-O tells you who wins as n grows, not who wins at every n.

9. Predict the output

Say the Big-O out loud first, then reveal.

for (i = 0; i < n; i++) for (j = 0; j < 100; j++) steps++;

O(n). The inner loop always runs 100 times, a constant. 100n drops to n.

for (i = 1; i < n; i *= 2) steps++;

O(log n). i goes 1, 2, 4, 8, ... and reaches n after about log₂ n doublings.

for (x of a) steps++; for (y of b) steps++; (a has n items, b has m)

O(n + m). Two loops one after the other add, and they have different sizes.

for (i = 0; i < n; i++) for (j = 1; j < n; j *= 2) steps++;

O(n log n). n outer rounds, each with a log n inner loop: multiply.

while (n > 0) n = n - 3;

O(n). About n / 3 steps. Subtracting a constant is linear; only dividing gives log n.

Exact count: for (i = 0; i < 4; i++) for (j = 0; j < i; j++) steps++;
