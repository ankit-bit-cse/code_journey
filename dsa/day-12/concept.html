Binary search on the answer

The last day of Phase 1, and the most powerful binary search: there is no array to search. You search the range of possible answers, and at each mid you ask one yes/no question: "is this enough?"

← Day 11All days

1. When the answer is a number

"What is the smallest reading speed that finishes the book in 6 hours?" There's no formula. But if someone hands you a guess, checking it is easy: add up the hours at that speed and compare with 6.

fast enough?nonononoyesyesyesyes

That row is monotonic: once the answer is "yes", it stays "yes" (reading faster never takes longer). So it's exactly the "no, no, yes, yes" picture from firstBadVersion yesterday, and the answer is the first yes. Binary search finds it in O(log range) checks instead of trying 1, 2, 3, 4, ...

The whole trick: turn "find the best value" into "is this value good enough?". If that yes/no question is monotonic, binary search the answer.

2. The template (smallest value that works)

let lo = SMALLEST_POSSIBLE, hi = BIGGEST_POSSIBLE, ans = -1;
while (lo <= hi) {
  const mid = Math.floor((lo + hi) / 2);
  if (canDo(mid)) {
    ans = mid;          // mid works: remember it...
    hi = mid - 1;       // ...and try to find a SMALLER one
  } else {
    lo = mid + 1;       // mid doesn't work: so nothing below it does either
  }
}
return ans;

It's the "save the answer and keep going" search from Day 10, but the "array" is the numbers lo..hi and reading it is calling canDo(mid). Invariant: ans always works, and any better answer is inside [lo, hi].

3. Watch it run: square root without Math.sqrt

The simplest example: the square root of 13, rounded down, is the largest r with r * r <= 13. The check is one multiplication. Since we want the largest, a "yes" means try bigger. Green = works, red = too big, grey = ruled out without checking.

14 candidates, 4 checks. For n = 2,000,000,000 it would be about 31 checks; trying r = 0, 1, 2, ... one by one would take about 44,700.

4. The recipe

  1. What is the answer? A whole number: a speed, a capacity, a day, a distance.
  2. The range. The smallest value it could possibly be (lo) and a value that surely works (hi). Usually the max, the min, or the sum of the input.
  3. The check. Write canDo(x) that answers yes/no, usually with one pass over the input, often greedy.
  4. Is it monotonic? If x works, does x + 1 work too? (or x - 1, for "largest")
  5. Search. Smallest that works: on yes go left. Largest that works: on yes go right.

Test canDo alone first. Almost every bug today is in the check, not the search. Run it by hand on the example for one value that should pass and one that should fail.

5. Watch it run: a feasibility check at every mid

A book has chapters of [9, 4, 7, 3] pages. Each hour you read from one chapter, up to speed pages (a chapter of 9 pages at speed 4 takes 3 hours: 4 + 4 + 1). What's the smallest speed that finishes in 6 hours? The speeds 1..9 are the boxes; the chips show the check for the current mid.

Each check costs one pass over the chapters, O(n), and there are O(log(max chapter)) checks, so it's O(n log max). Q3, Q5 and (with a different check) Q4 and Q7 all have this shape.

6. Largest value that works: "maximize the minimum"

Flip it around: "place 3 routers in these houses so the closest two are as far apart as possible." Now a smaller distance is easier, so the check row goes yes, yes, yes, no, no and we want the last yes: on yes, save it and go right (lo = mid + 1), just like the square root.

The check "can the routers all be at least d apart?" is greedy: put the first router in the first house (it never hurts to start as far left as possible), then walk right and put the next router in the first house that is at least d past the last one.

So 5 works and 6 doesn't: the answer is 5. The binary search over d decides which distances to check; the greedy pass answers each check in O(n).

7. How to spot it

  • "Minimize the maximum ..." (the largest part, the heaviest day) → smallest value that works.
  • "Maximize the minimum ..." (the closest distance, the smallest share) → largest value that works.
  • "the smallest speed / capacity / day / divisor such that ..." → smallest value that works.
  • The input is too big to try every answer, but checking one answer is a simple loop.

Get the range right. A ship must at least carry the heaviest package, so lo = max(weights), not 1 (with 1 the check would have to handle packages that never fit). And hi = sum(weights) always works: everything in one day. A wrong lo or hi is the second most common bug today.

8. Predict the output

Say the answer out loud first, then reveal.

Chapters [9, 4, 7, 3], speed 3: how many hours?

8. Math.ceil(9/3) + Math.ceil(4/3) + Math.ceil(7/3) + Math.ceil(3/3) = 3 + 2 + 3 + 1.

Ship weights [4, 1, 3, 2] with capacity 5: how many days?

2. Day 1: 4 + 1 = 5. Day 2: 3 + 2 = 5. The packages stay in order, so you can't pair 4 with anything else.

sqrtFloor search on 0..10: what is the first mid, and is it a yes?

5, and no: 5 · 5 = 25 > 10. So hi = 4, and half the range is gone with one multiplication.

"Is a speed of 0 fast enough?" Why does Koko's range start at 1?

At speed 0 she never finishes, and Math.ceil(p / 0) is Infinity. The smallest speed that could possibly work is 1.

Routers in houses [1, 2, 3], 3 routers: the best smallest distance?

1. Every house gets a router, so the closest two are 1 apart. With as many routers as houses, there's no choice to make.

where this shows up

"Koko eating bananas", "capacity to ship packages", "split array largest sum", "magnetic force between balls" (that's aggressive cows), "minimum days to make bouquets", "allocate minimum pages", "painters' partition": all one pattern. When a problem says minimize the maximum or maximize the minimum, try binary search on the answer first. Later, the same idea speeds up other algorithms whenever "is X possible?" is easier than "what is the best X?".
