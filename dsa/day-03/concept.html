Thinking recursively

A recursive function solves a big problem by trusting itself to solve a smaller copy of it. Today: how to design one in three steps, how to read the call stack, and how halving the problem makes power O(log n).

← Day 2Day 4 →

1. Three questions, every time

In JS for DSA Day 10 you met base cases and the call stack. Now we design recursion on purpose. Before writing any code, answer three questions:

  1. Base case: what is the smallest input, the one I can answer right away?
  2. Smaller problem: which smaller input of the same kind is inside my problem?
  3. Trust and combine: if a call on the smaller input already returns the right answer, how do I build my answer from it?
// The length of a string, without .length
function len(s) {
  if (s === "") return 0;        // 1. base case: the empty string
  return 1 + len(s.slice(1));    // 2. smaller: s without its first letter
}                                // 3. combine: one more than that

Trust, don't trace. When you write len(s.slice(1)), do not follow it in your head all the way down. Assume it works (it will, if the base case and the step are right) and only ask: "given that answer, what is mine?". This is called the leap of faith.

Notice the shapes: numbers get smaller with n − 1 or ⌊n / 10⌋, strings and arrays get smaller by dropping the first item (or by moving an index, Day 4).

The base case must be reachable. If the step jumps over it, the calls never stop. f(n) = f(n − 2) with base case n === 0 never stops for odd n: 3, 1, −1, −3, ... Use n <= 0 or add a base case for 1.

3. Watch it run: the call stack going down and coming back

countEven(n) counts the even digits of n. Each call takes the last digit, then waits on the stack for the call on the rest. On the way back up, each waiting call finishes its own little sum.

Down: the stack grows by one call per digit. Up: each call returns, and its answer is used by the call below. The depth here is the number of digits, so the stack uses O(digits) space.

4. Recursion vs loops

Anything a loop does, recursion can do, and the other way round. Pick the one that reads more clearly.

Stack space is real space. From Day 2: a recursion with depth n uses O(n) extra memory even if it creates no arrays, because every waiting call keeps its own variables on the stack.

5. Stack overflow

function down(n) {
  return down(n - 1);     // no base case!
}
down(5);   // RangeError: Maximum call stack size exceeded

The stack has a limit, around 10,000 frames in Node and browsers (it depends on the engine). You hit it in two ways:

  • a missing or unreachable base case: the calls never stop (a bug), or
  • a correct but very deep recursion: sumTo(100000) overflows even though it is right. Use a loop, or make the depth O(log n) (next section).

6. Fast power: halve the exponent

The obvious recursion pow(b, e) = b × pow(b, e − 1) makes e calls: O(e). But look:

3¹³ = 3⁶ × 3⁶ × 3     // e odd: square the half, times one more b
3⁶  = 3³ × 3³         // e even: just square the half
3³  = 3¹ × 3¹ × 3
3¹  = 3⁰ × 3⁰ × 3
3⁰  = 1               // base case

Each call halves the exponent, so there are only about log₂ e calls: O(log e). The one rule: compute the half once, store it in a variable, and multiply it by itself. Calling pow(b, half) twice would make two calls per level and lose the whole speed-up.

For e = 13: 5 calls and 7 multiplications instead of 13 calls. For e = 1,000,000,000: about 30 calls instead of a stack overflow.

7. Watch it run: two pointers, moved by recursion

The two-pointer reverse from JS for DSA Day 5, but the pointers are parameters with default values: each call handles the two outer items, then hands the inside to a smaller call. No slicing, so no copies.

// A default value is used when the caller leaves the argument out.
function greet(name = "friend") { return "hi " + name; }
greet();          // "hi friend"
greet("Ankit");   // "hi Ankit"

So the first call rev(a) gets lo = 0 and hi = a.length - 1 for free, and every recursive call passes its own values. The caller never sees the extra parameters.

Base case: when lo >= hi, zero or one item is left, so there is nothing to do. Q7 (palindrome) uses exactly this shape. The difference: instead of swapping, it compares, and a mismatch lets it stop early.

6: exponents 16, 8, 4, 2, 1, 0. That is log₂ 16 + 2.

function p(n) { if (n === 0) return; p(n - 1); console.log(n); } p(3) prints?

1, 2, 3. The log runs after the call returns, so it happens on the way back up, deepest call first. Swap the two lines and you get 3, 2, 1.

where recursion takes you

Recursion is the engine of half of DSA. Days 4–5 go further: recursion on arrays with an index, recursion trees with two calls per step, and memoization. Merge sort and quick sort (Days 8–9) are recursion that splits the array in half. Later, every tree and graph problem (depth-first search) and every "generate all combinations" problem (backtracking) is written this way.

Fast power is an interview classic ("implement pow(x, n)"), and its idea, halve the problem and reuse the half, is the same O(log n) you will meet again in binary search.
